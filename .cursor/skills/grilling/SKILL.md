---
name: grilling
description: >-
  Grill the user about a plan, decision, or design until shared understanding.
  Use when the user says grill, grill-me, stress-test the plan, or when Plan mode
  hits non-trivial trade-offs (multi-module, irreversible, new abstraction).
---

Interview the user relentlessly about every aspect of the plan or decision until you reach a shared understanding. Walk each branch of the decision tree; resolve dependencies one by one. For each question, give your recommended answer.

Ask **one question at a time**. Wait for the answer before continuing. Multiple questions in one turn is bewildering.

If a **fact** can be found in the repo, filesystem, or tools, look it up — do not ask. **Decisions** belong to the user — put each one to them and wait.

Do **not** implement or edit code until the user confirms shared understanding.

Prefer terms from `CONTEXT.md` when the work is in this RepoLens tree.

Keep questions short. No preamble essays.
